# 피드 작업 frontmatter v1

상태: 포맷 명세 초안. 이 문서는 작성·전달·앱 처리 규칙을 정의하며, 피드 생성기나 오늘의 루틴 앱에 구현되었다는 의미는 아니다.

## 목적

구독 피드의 Markdown 문서에 작업과 세부 작업을 선언한다. 사용자는 앱에서 피드의 작업 또는 세부 작업을 선택하여 오늘의 작업에 추가하고 시작·완료를 기록한다. 여기서 실행은 사용자의 작업 진행 기록이며, AI 호출·셸 명령·외부 서비스 자동 실행은 v1 범위에 포함하지 않는다.

## 문서 구조

UTF-8 Markdown 파일 시작의 `---` 구분자 사이에 YAML 매핑을 작성한다. 닫는 `---` 이후는 읽기용 본문이다. 일반 문서 메타데이터와 충돌하지 않도록 앱 설정을 `today_routine` 아래에 둔다.

전체 예시는 [주간 업무 점검](../examples/weekly-review.md)을 참고한다.

| 필드 | 타입 | 필수 | 규칙 |
| --- | --- | --- | --- |
| title | 문자열 | 아니오 | 문서 제목. 없으면 피드 항목 제목 사용 |
| date | 문자열 | 아니오 | 발행일, YYYY-MM-DD. YAML 날짜 변환을 피하도록 따옴표 사용 |
| today_routine | 객체 | 아니오 | 없으면 일반 읽기용 피드 |
| today_routine.version | 정수 | 예 | v1은 1 |
| today_routine.id | 문자열 | 예 | 같은 구독 안에서 고유한 문서 식별자 |
| today_routine.tasks | 배열 | 예 | 한 개 이상의 작업, 배열 순서대로 표시 |
| tasks[].id | 문자열 | 예 | 문서 안에서 고유한 작업 식별자 |
| tasks[].title | 문자열 | 예 | 공백만으로 구성되지 않은 작업명 |
| tasks[].duration_minutes | 정수 | 아니오 | 1 이상인 예상 총 소요 시간. 생략하면 미지정 |
| tasks[].steps | 배열 | 아니오 | 세부 작업 목록. 생략하거나 빈 배열이면 단일 작업 |
| steps[].id | 문자열 | 예 | 부모 작업 안에서 고유한 세부 작업 식별자 |
| steps[].title | 문자열 | 예 | 공백만으로 구성되지 않은 세부 작업명 |

ID는 소문자 영문·숫자로 시작하고 소문자 영문·숫자·하이픈·밑줄만 사용한다: `^[a-z0-9][a-z0-9_-]*$`.
제목·배열 순서·문서 경로가 바뀌어도 같은 작업이면 ID를 유지한다. 별개의 문서나 작업에는 새 ID를 부여한다. 세부 작업은 한 단계만 지원한다.

YAML 중복 키, 사용자 정의 태그, 앵커·별칭은 허용하지 않는다. 지정 필드의 타입 오류, 중복 ID, 지원하지 않는 버전은 실행 설정 오류로 처리한다. 알 수 없는 필드는 v1에서 무시하며 실행 의미를 부여하지 않는다. 실행 의미를 바꾸는 확장은 새 버전으로 정의한다.

## 앱 처리 규칙

아래는 구현 대상 동작이다.

1. 피드를 읽거나 갱신하는 것만으로 작업을 추가하거나 시작하지 않는다.
2. 상세 화면에서 작업 또는 세부 작업을 선택하고 ‘오늘의 작업에 추가’를 누른다. 일부 세부 작업만 선택하면 부모 작업과 선택한 세부 작업을 함께 추가한다.
3. 실행 날짜는 사용자가 추가할 때 정하며 기본값은 앱의 오늘 날짜다. 문서의 발행일을 실행 날짜로 자동 사용하지 않는다.
4. 작업과 세부 작업의 진행 상태는 앱에 저장한다. frontmatter에는 완료 여부나 실행 날짜를 기록하지 않는다.
5. 상태 표시는 기존 앱의 TODO / DOING / DONE / SKIPPED 규칙을 따른다.
6. 중복 판별 키는 구독 식별자 + 문서 ID + 작업 ID + 실행 날짜다. 같은 날짜의 재추가는 기존 작업으로 이동한다. 일부 단계만 추가한 경우 새로 선택한 단계만 병합하고 기존 단계의 상태는 보존한다.
7. 세부 작업 기록은 부모 작업 실행 키 + 세부 작업 ID로 식별한다. 다른 날짜에 추가하면 별개의 실행 기록이다.
8. 추가 시 제목·소요 시간·선택한 단계·출처를 스냅샷으로 보존한다. 피드 갱신·항목 삭제·구독 해제는 이미 추가한 작업과 진행 기록을 덮어쓰거나 삭제하지 않는다.
9. 잘못된 설정은 해당 문서의 작업 추가를 막고 오류를 안내한다. 읽기용 본문은 계속 표시한다. 유효한 문서의 frontmatter는 일반 본문 표시에서 제외한다.

앱 내부 일감의 구형 TaskItem 모델을 되살리거나 Apple 미리 알림에 자동 생성하는 것을 뜻하지 않는다. 오늘 화면과의 구체적인 저장·연결 구현은 별도로 진행한다.

## RSS/Atom 전달 계약

Markdown 원본에 설정이 있어도 발행기가 frontmatter를 제거하면 앱에서 작업을 찾을 수 없다. 발행기는 앞뒤 구분자를 포함한 원본 Markdown 전체를 본문에 보존해야 한다.

- RSS 2.0: `content:encoded`에 frontmatter를 포함한 Markdown 전체를 넣는다. CDATA를 쓰면 본문의 `]]>`를 적절히 분할한다. XML escape를 쓰면 파싱 후 원문이 복원되어야 한다.
- Atom: `content type="text/markdown"`에 frontmatter를 포함한 Markdown 전체를 XML escape하여 넣는다.
- HTML로 변환한 본문에 YAML을 섞거나 description/summary에만 일부 설정을 넣지 않는다.
- 앱은 XML을 해석한 원본 본문에서 먼저 frontmatter를 추출한 뒤 나머지 Markdown을 렌더링해야 한다. HTML/일반 텍스트 변환 이후 추출하면 안 된다.
- RSS guid / Atom id는 피드 항목 식별자다. today_routine.id는 문서의 실행 설정 식별자이며, 두 식별자의 역할을 구분한다.
- 기존 today-routine 피드 파서는 RSS/Atom 본문을 수집하지만 이 frontmatter 실행 설정은 아직 해석하지 않는다. RSS Markdown 판별과 메타데이터 분리 처리가 추가로 필요하다.

## 구현 확인 항목

- 예시 문서를 YAML로 읽어 필수 필드·타입·ID 고유성을 검증한다.
- RSS/Atom 왕복 후 frontmatter와 Markdown 본문이 보존되는지 확인한다.
- 설정 없음·오류·미지원 버전에서 본문 열람이 가능한지 확인한다.
- 같은 날짜 재추가, 일부 단계 추가, 다른 날짜 실행을 구분한다.
- 피드 수정·삭제 이후 기존 진행 기록이 유지되는지 확인한다.
